什么是 DID：把身份还给自己

一句话说清：DID 由你自己生成、自己保管，别人却仍能验证真伪。它要解决的是我们在网上「证明我是我」这件别扭事。

现在的身份，是平台借给你的

今天你在网上的身份，是一堆互不相通的账号：微信、银行、购物网站各一套。每个平台维护一张用户表，你只是里面的一行记录。

这带来两个问题。第一，记录不属于你。平台封号、清数据、停运，你积累的聊天、订单、评价就跟着消失，甚至找不到申诉对象。二是证明「我是我」很麻烦：注册要手机号，实名要上传身份证，办业务还要手持证件拍照。你把最敏感的原件交出去，却不知道它会被存多久、给谁看；平台说「已加密」，你只能相信。

DID：自己生成、自己保管的身份标识

DID 是 Decentralized Identifier 的缩写，中文常译作「去中心化标识符」。格式如：did:example:123456789abcdefghi。

关键在谁掌握它。普通账号由平台分配、保管、收回；DID 由你的软件生成，私钥留在你手里，没有公司能替你注销。私钥只有你知道，用来对操作签名，相当于这个身份的印章。

别人凭什么信？靠一个公开的「身份登记处」。它只存「这个 DID 对应哪些公钥」，不存姓名、住址、证件号。谁都能查，看到的是公开信息，不是你的档案。登记处可以是区块链，也可以是别的公共目录。

三个角色：DID、DID 文档、可验证凭证

DID 体系拆开看，是三样东西。

DID：身份标识

一个指向你的字符串，相当于名字，本身不携带个人信息，只负责被引用、被解析。

DID 文档：身份标识的公开档案

DID 文档（DID Document）是名字对应的公开档案，记录公钥、验证方法、服务地址。别人拿到 DID 解析出它，就能确认「用某把私钥签的名确实来自这个 DID」。

可验证凭证：别人签发给你的证明

可验证凭证（Verifiable Credential，简称 VC）是签发方给你的一段带数字签名的数据，比如学历证书、会员卡、驾照。签发方、内容、有效期都在里面，改一个字签名就失效。

三者串起来：学校给你签发 VC，你存在自己的钱包（保管私钥的软件）里；需要时出示，对方用 DID 文档里的公钥验签，确认证书没被篡改、确实由学校签发。

出示证明，而不是交出原件

VC 的第一属性是「可验证」：签名保证内容没被篡改、来源可查。隐私则是另一件事，要看具体方案。基础数据模型会把签发方签署的各个字段都放进凭证里，默认并不会替你藏起没出示的部分；只有 BBS+、SD-JWT、零知识证明这类支持可选择性披露的方案，才做得到「只让对方知道结论」。

举个例子。酒吧查年龄，传统做法是看身份证，姓名、住址、身份证号全被看光。若采用支持可选择性披露的方案，你的钱包可以基于学校签发的 VC，生成一份「已满十八岁」的派生证明：酒吧能验证这个结论来自学校的有效签名，却拿不到出生日期、住址等原始字段。要注意，「已满十八岁」通常不是你证书上直接写着的一个字段，而是从出生日期推导出来的结论；派生证明所做的，就是让密码学为这个推导背书。

这就是「出示证明而不交出原件」：证明某个事实成立，而不是把全部资料复印一份留在别人抽屉里。对个人是隐私，对机构是少存数据的责任。前提仍是选对方案：没有可选择性披露支持的 VC，出示时依旧会暴露签发方写入的全部内容。

三个必须澄清的误解

DID 不等于区块链专属。区块链是多方共同维护、难以篡改的公开账本，只是最常见的登记方式。但 DID 标准没绑定它：分布式文件系统、行业联盟目录，甚至受监管的公共机构都能做登记处。选哪种，取决于你想防谁。

DID 也不等于绝对匿名。它能改善隐私：你可以选择向谁出示哪些凭证（能否只露部分字段，仍取决于所用方案），但该实名时仍要实名。签发方发证时就知道你是谁，监管也可能要求可追溯。匿名和可验证是两件事。

最重要的一条：私钥丢了，没有「找回密码」。没有客服，没有密保问题，没有短信验证码。丢了私钥就失去了对身份的控制，别人也帮不上忙。常见取舍有两种：托管，把私钥交给服务商，方便但重新依赖中心；社交恢复，把恢复权限拆给几个信任的人或设备，用便利换容错。这不完美，却是清醒的取舍。

结语

DID 不是让你在网上隐形，而是把「我是谁、我出示什么」的决定权从平台手里挪回自己手里。代价是：自己保管密钥，理解签名和凭证，为丢失做准备。理解代价，比记住缩写更重要。
