Web3 与 DID：一个管账本，一个管身份

Web3 和 DID 常一起出现，分工却不同：Web3 解决「资产和规则由谁控制」，DID 解决「身份由谁控制」。

一、两个问题，两套工具

Web3 的主角是共同维护的账本：谁持有多少、按什么规则转移，都写在链上。 钱包和私钥管的是「这笔资产能不能动」。

DID 的主角是身份：DID 是别人引用你的字符串，DID 文档是它的公开档案，放着公钥；可验证凭证是机构签发的证明。 私钥管的是「这个身份是不是你在用」。

地址像门牌号，可公开收款；DID 更像身份证号，用来证明「我是我」。两者常一起用，比如在链上登记 DID 文档、 用钱包保管凭证，但也能分开：DID 的登记处不一定非是区块链。

二、出示一次可验证凭证，发生了什么

  1. 凭证在钱包里。学校把学历、专业和签发时间写成一份可验证凭证，签名后交给你保管。
  2. 网站发起请求。招聘方说：只要学历和专业，不要姓名、生日。
  3. 你只出示需要的字段。确认后只交「本科、计算机」两项。这要求凭证支持可选择性披露，否则会带出全部字段。
  4. 网站通过 DID 文档验证签名。解析签发方的 DID 文档，用里面的公钥验签，再核对有效期和吊销状态。
  5. 不需要联系发证机构。学校全程不知情，也不必为每次验证开接口。信任来自签名和公开档案。

三、两个具体场景

求职与学历验证

今天交截图、验证报告，或等 HR 打电话。截图能改，报告会过期。 换成凭证，招聘方验签名，几秒出结果，也不用交出整份成绩单。

KYC：只证明「已成年」

开户、买酒都要证明年龄，传统做法是拍身份证，生日、住址全被看光。 用零知识证明，钱包能生成「已满十八岁」的派生证明：对方确认结论来自有效签名，却拿不到出生日期。

四、局限与风险

  • 私钥管理。丢了没有「找回密码」，身份和凭证一起失去；交给托管又回到依赖平台。社交恢复是折中，但恢复过程也可能被利用。
  • 凭证吊销。验签只证明签发时是真的。证书被撤销、卡过期，要靠吊销列表或状态查询；名单不及时，结论就会错。
  • 隐私元数据。字段藏住了，痕迹还在：何时向谁出示、用的哪个 DID，都可能被关联。地址是化名，不是隐身。
  • 监管与互操作。各家的披露格式、DID 方法和吊销机制不统一，跨厂商常对不上；监管要求可追溯时，纯自持身份也会撞墙。

五、小结

合起来记：Web3 让账本不锁在一家公司手里，DID 让身份不锁在一个平台账号里。两者可搭着用，也可各用各的。
